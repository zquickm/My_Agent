# My_Agent 最终技术方案（dsh 架构 + Codex 式多 Agent + DeepSeek，从零手写）

## 已定案的决策
1. 多 Agent 协作系统；后端 Python 3.12 + FastAPI；核心逻辑从零手写；前端 Vue 3 + Vite
2. 架构参考 dsh（DeepSeek Harness）：事件溯源会话日志、工具注册表+流水线、Agent 注册表与循环分离、host/client 事件流分离
3. 专家 Agent 采用 Codex 式**静态注册表**：人格人为提前定义（name / description / system prompt / 工具面 / 模型），主 agent 运行时只做「选人 + 撰写任务 + 汇总」，不发明专家
4. 护栏（嵌套深度、并发上限、工具权限）全部硬编码在系统层，不靠 prompt 约束、不交给 LLM
5. LLM 用 **DeepSeek 官方 API**（OpenAI 兼容）：`deepseek-chat`（V 系列，function calling）为主力，专家可按需配 `deepseek-reasoner`；换其他供应商只改 base_url
6. 协作方式：我不动你的文件，所有代码在对话中分阶段给你（带讲解），你自己敲写运行，报错贴回来我帮你调

## 从 dsh 借鉴的 4 个核心设计

**1. 事件溯源会话日志（最关键）**
不存"聊天消息"，只存一份 append-only 事件日志（SQLite `events` 表：session_id, seq, type, agent, payload）。事件类型：`user_message` / `agent_start` / `text_delta` / `tool_call` / `tool_result` / `agent_end` / `error` / `done`。一切皆投影：
- 后端投影：events → OpenAI messages（LLM 历史是派生的，不是存的）
- 前端投影：连续 `text_delta` 折叠成消息节点、`tool_call`+`tool_result` 配对成工具卡片
- 刷新/重启后从同一份日志重建会话；事件天然记录 spawn 拓扑

**2. 工具注册表 + 执行流水线**
`@tool` 装饰器注册函数，pydantic 自动生成 JSON Schema。工具调用过中间件流水线：**权限门控（按 AgentSpec 的工具白名单硬拦截）→ 执行 → 输出截断**（防超长输出撑爆上下文）。

**3. Agent 注册表与循环驱动器分离**
`AgentSpec`（name、description、system prompt、工具集、模型配置）只是注册表里的数据；一个通用 `AgentLoop` 驱动器跑任何 AgentSpec。每个专家可独立配模型（如 supervisor 用 reasoner、explorer 用 chat）。

**4. host/client 分离 + 事件流**
后端驱动 Agent、追加事件、推流；前端是薄投影层。`POST /api/chat` + SSE 流式返回——**SSE 推的就是会话事件本身**，前后端共用同一套事件词汇表。

## 多 Agent 编排（Codex 式）
- **静态专家注册表**（`agents.py`）：每个专家一条 AgentSpec。`description` 写给主 agent 看（何时选我）；工具面按最小权限配置（explorer 类专家只有只读工具）
- **内置起步角色**（仿 Codex 的 default / worker / explorer）+ 领域专家自行添加
- **delegate(agent_name, task) 工具**：主 agent 调用它分派任务；执行 = 递归跑通用 AgentLoop，其 tool_result 即专家最终产出
- **硬护栏（代码层）**：`max_depth = 1`（专家不能再 delegate）、并发子 agent 上限、工具白名单拦截
- 可选演进（Phase 7）：delegate 加 `instructions` 补充指令参数

## 明确不搬的东西（防过度设计）
Cordis 插件系统 / 200+ 包 monorepo → 单包后端 + 注册表；Typert 类型化 RPC → pydantic + SSE；React/ui-slots → 普通 Vue 组件；沙箱/LSP/skill 能力家族 → 按需后加

## 技术栈
| 层 | 选型 |
|---|---|
| 后端 | FastAPI + uvicorn（ASGI 服务器，负责监听端口收发 HTTP）、`openai` SDK 指向 DeepSeek（base_url=https://api.deepseek.com）、pydantic v2、aiosqlite、uv |
| 前端 | Vue 3（`<script setup>`）+ Vite + Pinia + 原生 fetch/ReadableStream 解析 SSE + Tailwind CSS |
| 通信 | HTTP POST + SSE 流式（事件格式与日志统一） |
| 存储 | SQLite（一张 events 表起步） |

## 分阶段路线（每阶段有可运行里程碑，我给完整代码 + 逐段讲解）
- **Phase 0**：环境准备 — uv、Node 20+、DeepSeek API key（platform.deepseek.com）、`.env`、双项目骨架
- **Phase 1**：后端最小闭环 — 事件词汇表 + 内存版会话日志 + LLM 流式 SSE（约 150 行，无工具）
- **Phase 2**：前端最小闭环 — Vue 聊天界面消费 SSE，text_delta 折叠成消息节点（约 150 行）
- **Phase 3**：工具系统 + 单 Agent — @tool 注册表、通用 AgentLoop、执行流水线（权限门 + 截断）（约 250 行）
- **Phase 4**：持久化与恢复 — SQLite 事件表、会话列表、刷新后从日志重建会话
- **Phase 5**：多 Agent — AgentSpec 注册表（default/worker/explorer 起步）、delegate 工具递归调用、深度/并发硬护栏、事件按 agent 打标
- **Phase 6**：前端升级 — Agent 徽章、工具调用卡片、多 Agent 时间线视图
- **Phase 7（可选）**：代码执行沙箱、RAG、长输出溢出（spill）、delegate 补充指令参数、会话 fork
